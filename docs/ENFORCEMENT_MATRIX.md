# Heli v0.8.0 Enforcement Matrix

`Documented` means the protocol is explained. `Skill` means a routed workflow
resource exists. `CLI` means a structured transition is callable. `Hook` means
the shared evaluator is wired into a runtime hook/tool-call path. `Host` names
the proven scope. `CI/Test` is the local reproducible proof; it is not a
sandbox or a claim of universal host support.

| Behavior | Documented | Skill | CLI | Hook | Host | CI/Test |
| --- | --- | --- | --- | --- | --- | --- |
| Target discipline | HARNESS + target docs | heli-target | `target` | existing target guards | Pi/native adapters where wired | `smoke-cli-target` |
| Concurrent claim/lease | HARNESS + state README | heli-governance | `task claim` | ownership gate | shared supported hooks | `smoke-concurrency-foundation` |
| Premise vs fact | evidence-governed-autonomy | verify-premise + evidence-gates | `diagnosis init/record` | S2 active diagnosis write gate | shared PreToolUse/tool-call | `smoke-vnext-root-cause` |
| Closest proven boundary | evidence-governed-autonomy | verify-premise/debug | `init`, `record` | root-cause gate reads state | supported shared hooks | vNext scenario 1 |
| Hypothesis invalidation | evidence-gated skill/docs | debug + evidence-gates | `record evidence/classify` | reroute denial | supported shared hooks | vNext scenario 2 |
| Same/new failure routing | architecture doc | fix-loop + flow | `record run/route` | new-class write denial | supported shared hooks | vNext scenarios 3–4 |
| Subsystem checkpoint | architecture doc | impact + evidence-gates | `record checkpoint` | checkpoint denial | supported shared hooks | vNext scenario 5 |
| Expensive retry | safety policy + docs | evidence-gates/test-validation | `diagnosis gate` | structured `heli_action` | supported shared hooks | vNext scenarios 6–8 |
| Material decision observability | HARNESS + docs | engineering | `record decision` | state is surfaced | supported context hooks | CLI/state smoke |
| S1 autonomy | HARNESS + docs | engineering | no ceremony on success | no gate without diagnosis | all hosts advisory/enforced as applicable | vNext scenarios 9, 12 |
| S2 evidence + independent review | HARNESS + docs | engineering/audit | gate exposes review | evidence gate; reviewer status is structured | supported hooks | vNext scenario 10 |
| S3/human approval | safety + docs | engineering/evidence-gates | gate requires override | deny without human evidence | supported hooks | vNext scenario 11 |
| Verification/task completion | HARNESS + docs | test-validation/audit | `record run`, `task complete` gate | current state read | supported hooks | CLI/concurrency smokes |
| YOLO semantics | safety/yolo-mode + docs | evidence-gates | existing yolo CLI | ownership + vNext gates remain | supported hooks | `smoke-yolo-mode`, `smoke-vnext-hooks` |

Unsupported/advisory hosts must not be upgraded to `enforced` based only on
this table or a copied skill tree; the adapter support matrix remains the
runtime evidence authority.
