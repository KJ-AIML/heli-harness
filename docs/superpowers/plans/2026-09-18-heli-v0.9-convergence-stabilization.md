# Heli v0.9 Convergence Stabilization Plan

**Status:** Active implementation plan
**Architecture source:** `docs/superpowers/specs/2026-09-18-heli-v1-architecture-convergence.md`
**Branch:** `feat/v0.9-convergence-stabilization`

## Goal

Make the current v0.9 branch safe to stabilize by fixing correctness defects and collapsing divergent governance semantics onto a canonical path before any global-topology migration.

This plan deliberately does **not** implement the full v0.10 global distribution/project-binding architecture. It prepares the kernel so that migration can happen without carrying broken authority semantics forward.

## Slice 1 — Authority correctness

Targets C1, C3, C14.

- Revalidate conflicting worktree ownership on every expired-lease reacquisition.
- Prevent stale renewal from resurrecting a previous owner beside a new active writer.
- Separate delegable permission ceiling from current writer possession.
- Make parent/session closure affect descendant effective authority according to explicit rules.
- Add deterministic smoke coverage for stale renewal and descendant revocation.

Exit gate:
- no fixture can produce two active owners for the same modeled worktree resource through supported lease APIs;
- hierarchy smoke tests cover closure/revocation semantics.

## Slice 2 — Tool-surface authority parity

Targets C2.

- Remove mixed-path exemption behavior where one task-state path causes unrelated source mutations to bypass ownership checks.
- Classify supported structured mutation surfaces consistently.
- For shell-mediated writes that cannot be safely normalized, report partial/advisory coverage rather than implying equivalent enforcement.
- Add focused smoke fixtures for Edit, patch/multi-path operations, and shell commands.

Exit gate:
- supported structured source mutation surfaces agree on ownership decisions;
- uncovered shell semantics are explicit.

## Slice 3 — Canonical decision model and explain parity

Targets C4, C7, C9.

- Define one canonical governance decision/receipt constructor.
- Route runtime recording through that representation or a lossless projection.
- Make `explain current` consume the same evaluator path as enforcement with mutation disabled.
- Preserve historical decision inputs needed for bounded explanation.
- Make trace completeness explicit.

Exit gate:
- fixed snapshot => evaluator and explain return the same decision;
- runtime and protocol decision records share one schema contract.

## Slice 4 — Human/machine transition parity

Targets C5.

- Extract canonical application transitions for task/session/lease mutation.
- Human CLI and machine API become transport/rendering layers over those transitions.
- Close known takeover/completion parity gaps.
- Add parity smoke tests.

Exit gate:
- equivalent inputs create equivalent authoritative state through human and machine surfaces.

## Slice 5 — Capability truthfulness and identity

Targets C6, C8, C10.

- Extend runtime observations with host/runtime identity and invalidation-relevant metadata.
- Combine declared adapter contract and valid runtime observations in capability explanation.
- Do not treat callback observation as broad enforcement.
- Namespace external host session identity.
- Verify packaged entrypoints, not only source imports.

Exit gate:
- stale or mismatched observations are not reported as current enforcement;
- identical external session strings from different host/runtime identities cannot collide.

## Slice 6 — Low-friction compatibility foundation

Supports the v1 RFC without topology migration.

- Keep S0-S3 as workflow/UX summaries only.
- Ensure workflow helpers do not grant authority.
- Keep ACP and learning explicitly experimental.
- Keep generated workspace copies as generated compatibility artifacts.
- Preserve old event readers and compatibility paths.

Exit gate:
- no stable API implies that workflow tier itself authorizes an action;
- compatibility tests remain green.

## Verification

Run all existing v0.9 smoke/release checks plus new conformance-focused tests.

Minimum new scenarios:
- C1 stale renewal;
- C2 structured write-surface parity;
- C3 delegation/revocation;
- C4 explain parity;
- C5 machine/human lifecycle parity;
- C6 capability freshness;
- C7 unified decision shape;
- C8 packaged entrypoint truth;
- C9 trace completeness declaration;
- C10 host session namespace.
